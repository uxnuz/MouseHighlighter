# 구조와 설계

이 문서는 코드가 **어떻게 동작하는지**와 **왜 이렇게 만들었는지**를 설명합니다.
구체적인 수정 방법은 [수정-가이드.md](수정-가이드.md)를 보세요.

- 언어/프레임워크: C# / WPF (.NET 10, Windows 전용)
- 트레이 아이콘과 색 선택 창만 WinForms 기능을 빌려 씁니다.
- 외부 NuGet 패키지는 쓰지 않습니다. 필요한 Windows 기능은 `NativeMethods.cs` 에서 직접 호출합니다.

---

## 1. 파일별 역할

| 파일 | 역할 | 이럴 때 이 파일을 보세요 |
|---|---|---|
| `App.cs` | 프로그램 시작점. 커서 원, 마우스 훅, 트레이 아이콘, 설정 창을 만들고 연결합니다. **무엇을 켜고 끌지는 `UpdateActiveState()` 한 곳에서만 결정합니다.** | 트레이 메뉴, 시작 옵션, 켜기/끄기 동작 |
| `Settings.cs` | 모든 설정값과 기본값. JSON 파일로 저장하고 불러옵니다. 값이 바뀌면 `Changed` 이벤트로 알립니다. | 기본값 변경, 설정 항목 추가 |
| `OverlayWindows.cs` | 화면에 그리는 투명 창들. `OverlayWindow`(공통 설정), `CursorCircleWindow`(커서 원), `RippleWindow`(클릭 물결)가 있습니다. | 효과 모양이나 애니메이션 변경 |
| `MouseHook.cs` | 전역 저수준 마우스 훅. 어느 프로그램 위에서 클릭하든 버튼 종류와 위치를 알려 줍니다. | 감지할 마우스 동작 추가 (버튼 떼기, 휠 등) |
| `NativeMethods.cs` | Windows API(user32/kernel32) 선언과, 클릭이 통과하는 창 만들기, 물리 픽셀 위치로 창 옮기기 같은 도우미 함수 | Win32 기능 추가 |
| `TrayIcon.cs` | Windows 기본 화살표 커서를 큰 크기로 읽어서, 화살표 부분만 잘라 트레이 아이콘을 만듭니다. | 트레이 아이콘 변경 |
| `app.ico` | exe 파일 아이콘(탐색기·바탕 화면·작업 표시줄)과 설정 창 제목 표시줄 아이콘. 16~256px 크기를 담고 있습니다. | exe 아이콘 변경 |
| `SettingsWindow.xaml` | 설정 창의 화면 배치(XAML) | 화면 구성, 문구, 범위, 배경색 목록 |
| `SettingsWindow.xaml.cs` | 설정 창의 동작. 컨트롤 값을 바꾸면 `Settings` 에 반영합니다. | 컨트롤 동작 |
| `app.manifest` | PerMonitorV2 DPI 모드 선언 (아래 3-2 참고) | 거의 고칠 일 없음 |
| `MouseHighlighter.csproj` | 프로젝트 설정, 그리고 공유용 exe를 맨 위로 복사하는 `CopyExeToRoot` 작업 | 빌드 설정 |
| `Properties/PublishProfiles/Share.pubxml` | 공유용 단일 exe를 만드는 설정 | 배포 방식 변경 |
| `exe 다시 만들기.bat` | 실행 중인 앱 종료 → exe 빌드 → 빌드 중간 파일 정리 | — |

## 2. 동작 흐름

### 2-1. 시작
```
Main()
 ├─ 이미 실행 중이면 종료 (Mutex "MouseHighlighter_SingleInstance")
 └─ App.OnStartup()
     ├─ Settings.Current  ← %AppData%\MouseHighlighter\settings.json 읽기 (없거나 깨졌으면 기본값)
     ├─ CursorCircleWindow 생성
     ├─ UpdateActiveState()  ← 켜야 할 것만 시작
     ├─ 트레이 아이콘 생성
     └─ (--settings 옵션이 있으면) 설정 창 열기
```

### 2-2. 켜기/끄기 판단 (`App.UpdateActiveState`)
```
커서 원 동작  = 전체 켜짐(트레이) AND CircleEnabled(설정)
클릭 효과 동작 = 전체 켜짐(트레이) AND ClickEffectEnabled(설정)
```
- 커서 원이 꺼지면 창을 숨기고, 커서 위치를 확인하는 타이머도 멈춥니다.
- 클릭 효과가 꺼지면 마우스 훅을 아예 해제합니다(`MouseHook.Dispose`).
- 이 판단은 설정이 바뀔 때(`Settings.Changed`)와 트레이에서 켜고 끌 때 다시 실행됩니다.

### 2-3. 커서 원이 따라가는 방식
```
타이머가 CursorUpdateIntervalMs(기본 33ms, 초당 약 30회)마다
 └─ FollowCursor()
     ├─ GetCursorPos() 로 커서 위치 읽기 (물리 픽셀)
     ├─ 지난번과 같으면 아무것도 안 함
     └─ 다르면 CenterWindowAt() 로 원 창의 중심을 커서 위치로 옮김
```

### 2-4. 클릭 효과
```
사용자가 어느 프로그램에서든 클릭
 └─ Windows → MouseHook.HookCallback()  (UI 스레드에서 실행)
     ├─ 버튼 누름(왼쪽/오른쪽/휠)이면 ButtonDown(버튼, x, y) 알림
     │   └─ App.OnButtonDown() → 버튼에 맞는 색으로 RippleWindow 를 새로 만들어 띄움
     │        └─ 0.45초 동안 커지면서 투명해지는 애니메이션 → 끝나면 스스로 Close()
     └─ CallNextHookEx() 로 클릭을 원래 프로그램에 그대로 전달
```

### 2-5. 설정 변경
```
설정 창에서 슬라이더·숫자·색·체크박스 조작
 └─ Settings.Current 값 변경
     └─ Apply() → 화면 숫자·색 상자 갱신 + Settings.NotifyChanged()
         ├─ CursorCircleWindow.ApplySettings()  → 원 모양 즉시 변경
         └─ App.UpdateActiveState()             → 켜기/끄기 즉시 반영
설정 창 닫기 / 앱 종료
 └─ Settings.Save() → settings.json 에 저장
```
클릭 물결은 클릭할 때마다 새로 만들어지므로, 만드는 순간의 `Settings.Current` 값을 그대로 씁니다. 그래서 따로 연결하지 않아도 바뀐 설정이 다음 클릭부터 적용됩니다.

## 3. 설계 결정 (왜 이렇게 만들었나)

### 3-1. 화면 전체를 덮는 창 대신, 효과 크기만 한 작은 창을 움직입니다
화면 전체를 덮는 투명 창 하나에 그리면 구조는 단순합니다. 하지만 WPF에서 투명 창(`AllowsTransparency`)은 창 전체를 소프트웨어로 다시 그리기 때문에, 화면이 클수록 CPU를 많이 씁니다.
그래서 지름 60px 정도의 작은 창을 커서 위치로 옮기는 방식을 택했습니다. 클릭 물결도 클릭마다 작은 창을 하나씩 만듭니다. 빠르게 여러 번 클릭하면 물결이 겹쳐서 각각 보입니다.

### 3-2. 창 위치는 물리 픽셀 단위로 직접 옮깁니다 (`app.manifest` 의 PerMonitorV2)
모니터마다 배율(100%, 125%, 150%)이 다르면 WPF의 `Left`/`Top`(DIP 단위)과 실제 커서 좌표가 어긋납니다.
그래서 앱을 PerMonitorV2 DPI 모드로 실행합니다. 이 모드에서는 커서 좌표(`GetCursorPos`, 훅 좌표)가 항상 물리 픽셀 단위로 나오고, 창도 `SetWindowPos` 로 물리 픽셀 단위로 옮깁니다. 이때 창 크기만 DIP를 물리 픽셀로 바꿔서 계산합니다(`NativeMethods.CenterWindowAt`).

### 3-3. 클릭이 통과하는 창 (`NativeMethods.MakeClickThrough`)
효과 창에 Win32 확장 스타일을 붙입니다.
- `WS_EX_TRANSPARENT` + `WS_EX_LAYERED`: 마우스 클릭이 창을 통과해 아래 프로그램으로 갑니다.
- `WS_EX_NOACTIVATE`: 효과 창이 나타나도 입력 중이던 창의 포커스를 뺏지 않습니다.
- `WS_EX_TOOLWINDOW`: 작업 표시줄과 Alt+Tab 목록에 나오지 않습니다.

### 3-4. 커서 추적은 33ms 간격 타이머(`DispatcherTimer`)로 합니다
처음에는 WPF가 화면을 그릴 때마다(`CompositionTarget.Rendering`, 보통 초당 60번) 확인했습니다. 그런데 이 방식은 WPF가 그리기 루프를 계속 돌려서, 마우스가 가만히 있어도 CPU를 썼습니다.
지금은 33ms(초당 약 30회)마다 커서 위치를 확인하고, 위치가 그대로면 아무것도 하지 않습니다. 같은 PC에서 두 방식을 번갈아 10초씩 측정한 결과는 다음과 같습니다.

| 상황 | 예전 방식 (매 프레임) | 지금 방식 (33ms 타이머) |
|---|---|---|
| 마우스가 가만히 있을 때 | 281ms | 31~78ms |
| 마우스를 움직일 때 | 688~1,000ms | 578ms |

초당 30회면 눈으로 따라가기에 충분히 부드럽습니다. 간격은 `settings.json` 의 `CursorUpdateIntervalMs` 로 바꿀 수 있고, 값이 작을수록 부드럽지만 CPU를 더 씁니다.
커서 강조를 끄면 타이머를 멈춰서 CPU 사용량이 0이 됩니다.

### 3-5. 클릭 감지는 저수준 전역 마우스 훅(`WH_MOUSE_LL`)을 씁니다
DLL을 다른 프로그램에 넣을 필요가 없고, 이 프로세스 안에서만 동작해서 가장 간단하고 안전한 방법입니다.
클릭을 가로채지 않고 `CallNextHookEx` 로 그대로 넘깁니다. 훅 콜백이 느리면 PC 전체의 마우스가 버벅이므로, 콜백에서는 창 하나를 띄우는 일만 합니다.

### 3-6. 설정은 `%AppData%` 에 JSON으로 저장합니다
- exe가 어디에 있든 상관없이 같은 곳에 저장됩니다. 그래서 exe를 옮기거나 새 버전으로 바꿔도 설정이 유지됩니다.
- 사용자마다 따로 저장되므로, 폴더를 압축해서 공유해도 내 설정이 다른 사람에게 넘어가지 않습니다.
- 공개 속성이 그대로 JSON 항목이 됩니다. 새 속성을 추가해도, 예전 파일에 없는 항목은 기본값이 쓰여서 기존 설정이 깨지지 않습니다.

### 3-7. 공유용 exe는 '자체 포함 단일 파일'로 만듭니다
- .NET 런타임과 WPF 네이티브 DLL까지 exe 하나에 넣었습니다(`Share.pubxml`). .NET이 없는 PC에서도 실행되고, exe만 따로 옮기거나 zip 안에서 바로 실행해도 동작합니다.
- 대신 파일 크기가 약 72MB입니다.
- 실행할 때 네이티브 DLL을 `%TEMP%\.net\MouseHighlighter\` 에 풀어서 씁니다.
- 출력 폴더를 프로젝트 폴더로 바로 지정하면 SDK가 소스 파일을 빌드에서 빼 버립니다. 그래서 `bin\share\` 에 만든 뒤 `CopyExeToRoot` 작업이 맨 위로 복사합니다.

### 3-8. XAML 없이 코드로 만든 부분과 XAML로 만든 부분
- `App`, 효과 창들은 구조가 단순해서 코드로만 만들었습니다. 그래서 `App.xaml` 이 없고, `Main` 을 직접 둡니다.
- 설정 창은 컨트롤이 많아서 XAML(`SettingsWindow.xaml`)로 배치하고, 동작만 `.xaml.cs` 에 둡니다.

## 4. 설정값 목록 (`Settings.cs`)

| 속성 | 기본값 | 설정 창에서 | 설명 |
|---|---|---|---|
| `CircleEnabled` | `true` | 체크박스 | 커서 강조 켜기/끄기 |
| `CircleColor` | `#FFE600` | 색 | 원 색 (노랑) |
| `CircleDiameter` | `60` | 범위 20~300 | 원 지름 (100% 배율 기준 픽셀) |
| `CircleOpacity` | `0.3` | 투명도 (70%) | 안쪽 불투명도. 테두리는 이 값의 2.5배(최대 1)로 더 진하게 |
| `CircleBorderThickness` | `2` | — | 테두리 두께 |
| `CursorUpdateIntervalMs` | `33` | — | 커서 위치를 확인하는 간격(ms). 33 = 초당 약 30회 |
| `ClickEffectEnabled` | `true` | 체크박스 | 클릭 효과 켜기/끄기 |
| `LeftClickColor` | `#FF3C3C` | 색 | 왼쪽 클릭 (빨강) |
| `RightClickColor` | `#288CFF` | 색 | 오른쪽 클릭 (파랑) |
| `MiddleClickColor` | `#28C85A` | 색 | 휠 클릭 (초록) |
| `RippleDiameter` | `90` | 범위 30~300 | 물결이 퍼지는 최종 지름 |
| `RippleOpacity` | `0.9` | 투명도 (10%) | 물결이 처음 나타날 때의 불투명도 |
| `RippleDurationMs` | `450` | — | 물결이 사라지기까지 걸리는 시간(ms) |
| `RippleThickness` | `4` | — | 물결 선 두께 |

설정 창에 없는 항목(`—`)도 `settings.json` 을 직접 고치면 바뀝니다. 앱을 종료한 상태에서 고치세요.
